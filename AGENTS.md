# FloraFauna Frenchies

This checkout builds Fabric and NeoForge targets for Minecraft 26.1 and 26.3 with Java 25 and its checked-in Gradle wrapper. Check `versions/<minecraft-version>-<loader>/gradle.properties` for dependency versions. Shared code and resources live under `src/main`. Loader-specific sources live under `src/fabric` and `src/neoforge`. Version-specific resources live under `versions/<minecraft-version>/resources` and target overrides under `versions/<minecraft-version>-<loader>/target`. The 26.4 Fabric preview builds on Pre-Release 1 with `:26.4-fabric:build` and `:26.4-fabric:runGameTestServer`. See the README for the opt-in NeoForge Snapshot 10 target and its loader prerequisite. Keep gameplay, equipment, crafting and player interfaces shared across the Minecraft targets. Use target-specific code for Minecraft, loader or optional provider API differences. Preserve existing entity, item, attachment, courier-save and resource identifiers when changing persistence. The standalone mod owns its tests under `florafauna_frenchies`.

The 26.1 artifacts also support 26.1.1 and 26.1.2. CI starts the packaged 26.1 jars on both hotfixes and summons a Frenchie. When extending support, also join a dedicated server with the same jar and verify front-pack pickup, rendering, and release.

Add gameplay GameTests under `src/sharedGameTest` and register them in `CompanionTests` so both loaders run the same cases with the same IDs, structures and timing. The Fabric test mod under `src/gametest` also exercises Fabric's targeting and packed-courier hooks.

During iteration, run the smallest check that exercises the change. Run the target’s `test` task for value and timing rules. For world behavior, run a filtered headless case, for example `./gradlew '-PgameTestFilter=florafauna_frenchies:frenchie_bedtime' :26.1-neoforge:runGameTestServer`. Run the four targets' `build` and `runGameTestServer` tasks on an integrated revision for a substantial final pass or release. Inspect the selected test names, counts and failures. CI checks each loader and version. Draft PRs get `check`. Ready PRs and pushes to main get builds and the headless suite.

Independent headless and scripted-client checks can run concurrently when their build outputs, game directories and ports are separate. Each target writes under `versions/<minecraft-version>-<loader>/build`, `run` and `.tmp`. Use the workspace `Invoke-MinecraftCheck.ps1` launcher and include every checkout a run can write. Reserve the desktop lock for steps using Windows input, focus or desktop capture.

For NeoForge input, HUD, dialog, rendering or save/rejoin behavior, run the matching real-client scenario with `scripts/test_dev_world.ps1 -Target 26.1` or `-Target 26.3`. Use `scripts/test_delivery_multiplayer.ps1 -Target 26.1` for courier handoffs and `scripts/test_playful_interactions.ps1 -Target 26.1` for playful poses; choose 26.3 with either script for that version. The scripts default to 26.1, keep disposable game directories, and use separate ports for multiplayer runs. The singleplayer script requires a closed source world. Report which scenario, target and revision were verified.
